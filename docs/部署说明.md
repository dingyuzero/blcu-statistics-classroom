## 分支关系

main 保存源码、package-lock、测试、文档、许可证和 dist。gh-pages 根目录保存 dist 内容，另有 .nojekyll 和应用许可。Pages 设置为 **Deploy from a branch → gh-pages → /(root)**。

只推送 main 不会自动更新网页。当前没有 GitHub Actions 构建工作流；需要将检查过的 dist 同步到 gh-pages。

## 更新步骤

1. 克隆公开仓库，在 main 修改、提交源码。执行 npm ci、npm test、npm run check:assets，并通过本地服务查看改动。
2. 同步 docs 与 dist/docs 的三个文件，递增版本和 index.html 自有脚本的版本查询参数，避免旧缓存。
3. 运行 `npm run build:portable -- "release/统计课堂-单文件.html"`，试用图形、CSV、文档与许可证下载。
4. 单独准备 gh-pages 工作目录，例如 `git worktree add ../statistics-pages gh-pages`。核实目录确属目标仓库后，将 dist 内容同步到根目录，保留 .git 管理文件和 .nojekyll。检查差异，提交并普通推送 gh-pages；无需强制推送。
5. 查看 Pages 构建状态。打开公开网址强制刷新，核对新内容和关键交互。
6. 创建新 Release，目标设为对应 main 提交。上传单文件、源码 ZIP、静态离线 ZIP、三份 Markdown、完整包和 SHA256SUMS。

发布资产采用 ASCII 名称并给中文显示标签，避免 GitHub 对中文文件名的标准化碰撞。建议：statistics-classroom-offline.html、blcu-statistics-v2-source.zip、blcu-statistics-v2-offline.zip、blcu-statistics-v2-complete.zip、user-guide.md、developer-handoff.md、deployment-guide.md、SHA256SUMS.txt。

## 离线与其他托管

单文件 HTML 可通过 U 盘、网盘、邮件复制给其他电脑。用现代浏览器打开，不需要安装 Node、Python 或统计软件。别改成 txt；已下载文件在断网时仍能计算。文件较大是因为内置库和字体。

多文件版需复制完整目录；只复制 index.html 会丢失依赖。临时 Python 服务关闭后 localhost 地址不再可访问。打开其他电脑不能使用原电脑的 127.0.0.1 地址。

也可将 dist 上传任何静态托管服务，hash 路由无需 SPA 服务器重写。项目无数据库、密钥或环境变量；不要把凭据写入 HTML。

## 排错与回滚

- Pages 404：确认公开仓库、gh-pages 根路径、根目录 index.html，并等待构建。
- 内容仍旧：Ctrl+F5，确认更新的是 gh-pages；离线版需重新下载。
- 图形为空：检查 Console 和 vendor 路径完整性，重新解压整包或下载单文件。
- 回滚：git revert 问题提交，或把前一验证发布的 dist 作为新的普通提交发布，保留历史。
- 更名仓库：同步 README、三份文档、指南下载地址和 Release 链接。

Sites 私有镜像与 GitHub 独立部署，不将其托管元数据、运行目录或凭据混入公开源码。
